# ふたりの予定帳

2人で共有する仕事用のスケジュール管理アプリです。PC・スマホのブラウザ（Chromeなど）から使えます。

- 画面：`index.html`（HTML / CSS / JavaScript、1ファイル）
- データベース：Supabase（PostgreSQL＝SQL）… `schema.sql` でテーブルを作成
- ログイン：なし（v3〜）。URLを開くとすぐ使える。最初に「あなたはどちらか」を選び、その端末のブラウザに記録
- 公開：GitHub Pages（無料）

## 機能
- 月カレンダー表示（スマホでは予定を色の点で表示）
- 予定の追加・編集・削除（件名／開始日・終了日／開始・終了時刻または終日／担当／種類／メモ）
- 日をまたぐ予定（例：10/5 14:00 〜 10/7 12:00、10/5〜10/7 の終日）
- 担当の選択（1人目／2人目／2人共通）。担当ごとに色分け（1人目＝青、2人目＝オレンジ、2人共通＝紫）。2人共通には「共」の印も表示
- 誰が最後に更新したかを表示（表示名）
- 相手が変更すると、自分の画面も自動で更新（Supabase Realtime）
- シフトボード（バイトのシフト管理アプリ）のシフトを取り込み（v4〜）。iPhone の「ショートカット」アプリから送る。手順は `shiftboard_import.md`
- 件名を入力すると、前に登録した予定を候補に表示。選ぶと時刻・種類・担当・メモも入る（v5〜。シフトボードの取り込み分は候補に出さない）
- 毎週くり返す予定の登録（v5〜）。例：水木金の 9:00〜16:00 を1か月。1回で最大200件。削除のときに「この日だけ」か「この日以降のくり返しをすべて」を選べる

## ファイル構成
| ファイル | 内容 |
|---|---|
| index.html | アプリ本体（公開するのはこれだけ） |
| schema.sql | データベース定義・全体版（新しく作るときに Supabase の SQL Editor で1回実行） |
| migration_v2.sql | v2 の変更分（期間・担当）。v1 から更新するときに1回実行 |
| migration_v3.sql | v3 の変更分（ログインなし）。v2 から更新するときに1回実行 |
| rollback_v3.sql | v3 を元に戻す（ログインしていない人の読み書きを禁止） |
| migration_v4.sql | v4 の変更分（シフトボードの取り込み）。v3 から更新するときに1回実行 |
| migration_v5.sql | v5 の変更分（くり返し登録）。v4 から更新するときに1回実行 |
| shiftboard_import.md | シフトボード取り込み用の iPhone ショートカットの作り方 |
| README.md | この説明 |

## データベースの設計
- `profiles`：利用者（2人）の表示名。担当の選択肢と色の順番はこの表の id の順。名前は Supabase の Table Editor で変更できる
- `events`：予定。`event_date`（開始日）〜`end_date`（終了日）、`assignee`（担当、空欄＝2人共通）。`created_by` / `updated_by` / 日時はトリガーでサーバー側が自動記録
- v3 から、ログインしていない人（anon）も予定を読み書きできる設定（RLS ポリシー `events_anon_all`）
- v4 から、`events.source`（空欄＝画面から登録、`shiftboard`＝シフトボードから取り込み）と種類 `shift`（シフト）を追加。取り込みは関数 `import_shifts(p_member, p_lines)` で、これから先60日分の取り込み済みシフトをシフトボードの内容で置き換える
- v5 から、`events.series_id`（同じくり返しで登録した予定に同じ番号、空欄＝くり返しではない）を追加。くり返しは1日ずつ別の予定として保存する

## 注意
- **ログインがないため、アプリのURLや、公開している index.html の接続情報を知った人は誰でも予定を見たり書き換えたりできます。** 他人に知られて困る予定は書かないでください。ログインありに戻すときは rollback_v3.sql を実行し、v2 の index.html に戻します。
- Supabase の無料プランは、1週間使われないとプロジェクトが一時停止します。データは消えず、Supabase の管理画面から再開できます。
- `index.html` に書く「publishable キー（または anon キー）」は公開してよいキーです。`secret` キーや `service_role` キー、パスワードは絶対に書かないでください。
